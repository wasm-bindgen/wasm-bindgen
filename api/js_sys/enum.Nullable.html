Enum Nullable 

Source 
pub enum Nullable<T> {
    Null,
    Value(T),
}
Expand description

A T or null at the JS boundary.

Nullable<T> is the Rust-side type for a JS value of type T | null, as Option<T> is for T | undefined, and Option<Nullable<T>> is the union T | null | undefined. All three are accepted in the same positions: as an argument or return value of exported and imported functions, as a public field of an exported struct, and as a closure argument or return value, including the &/&mut reference forms Option<T> supports.

TypeJS typeJS → RustRust → JS
Option<T>T | undefinedundefined and null → None; anything else goes to T’s conversionNone → undefined
Nullable<T>T | nullnull → Null; anything else, undefined included, goes to T’s conversionNull → null
Option<Nullable<T>>T | null | undefinedundefined → None, null → Some(Null), else Some(Value(..))None → undefined, Some(Null) → null

The Option layer of Option<Nullable<T>> treats only undefined as None, since null has to reach the Nullable layer. opt.and_then(Nullable::value) collapses the union to an Option<T>. No other nesting is supported: Nullable<Nullable<T>>, Nullable<Option<T>> and Option<Option<T>> do not cross the boundary.

Both may also name a slot of a js-sys Function<fn(..)> signature or a Promise<T> resolution. Where a js-sys container’s type-erased methods marshal the element itself, as Array::get and Map::get do, the element must be a handle: use the JS-side JsOption<T> and JsNullable<T> there, which stay JS values rather than converting.

const NULLABLE: bool = true

Whether Self accepts null as a distinct value space, as Nullable<T> does. An enclosing Option then passes null through instead of reading it as None, so Option<T> is itself nullable exactly when T is not. JsValue does not set this: it accepts null as one value among all of them, not as a distinct space, and Option<JsValue> reads it as None like the ABI does. This is the JS-value side of NullableFromWasmAbi, which claims null at the ABI.
