Enum Nullable 

Source 
pub enum Nullable<T> {
    Null,
    Value(T),
}
Expand description

A T or null at the JS boundary.

Nullable<T> is the Rust-side type for a JS value of type T | null, as Option<T> is for T | undefined, and Option<Nullable<T>> is the union T | null | undefined. All three are accepted in the same positions: as an argument or return value of exported and imported functions, as a public field of an exported struct, and as a closure argument or return value, including the &/&mut reference forms Option<T> supports.

TypeJS typeJS → RustRust → JS
Option<T>T | undefinedundefined → None; anything else, null included under wasm_bindgen_unstable_strict_option, goes to T’s conversionNone → undefined
Nullable<T>T | nullnull → Null; anything else, undefined included, goes to T’s conversionNull → null
Option<Nullable<T>>T | null | undefinedundefined → None, null → Some(Null), else Some(Value(..))None → undefined, Some(Null) → null

The Option layer of Option<Nullable<T>> always treats only undefined as None, with or without the cfg, since null has to reach the Nullable layer. opt.and_then(Nullable::value) collapses the union to an Option<T>. No other nesting is supported: Nullable<Nullable<T>>, Nullable<Option<T>> and Option<Option<T>> do not cross the boundary.

Use these for a value crossing the boundary directly. Inside a JS type, such as Array<T> or Promise<T>, and in generic positions, use the JS-side handles JsOption<T> and JsNullable<T> instead, which stay JS values rather than converting.
