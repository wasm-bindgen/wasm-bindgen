Struct SafeInteger 

Source 
pub struct SafeInteger<T: SafeIntegerPrimitive>(/* private fields */);
Expand description

A u64 or i64 that crosses the JS boundary as a number instead of a BigInt.

Many JS APIs type integer counts as number. A plain u64 in a binding signature is a BigInt at the boundary, so SafeInteger<u64> is used instead to keep the Rust integer type while passing a number. In TypeScript it is number.

ⓘ
use wasm_bindgen::SafeInteger;

#[wasm_bindgen]
extern "C" {
    type QueueMetrics;
    #[wasm_bindgen(method, getter, js_name = backlogCount)]
    fn backlog_count(this: &QueueMetrics) -> SafeInteger<u64>;
}

let count = metrics.backlog_count();
if count > 10_000 { /* ... */ }
let next: u64 = (count + 1).into();

It derefs to the inner integer, so its methods are available directly, and compares and does arithmetic with both itself and the inner type.

The value is expected to be within ±(2^53 - 1) (Number.MAX_SAFE_INTEGER) and, for u64, non-negative, so that it is exactly representable as a JS number. Like the overflow checks on Rust’s own integers, this is only checked with debug assertions enabled: constructing a value out of range, arithmetic leaving the range, or receiving a non-integer or out-of-range number from JS then panics. Without debug assertions an out-of-range value converts lossily, as an as cast would. SafeInteger::new and the TryFrom<JsValue> conversion always check.

SafeInteger is supported in every position its conversion is reached through: arguments and returns, catch results, Option, Vec and Box<[_]>, borrowed slices passed into Rust, closure arguments, async import results and generic positions on experimental_generic_mono imports. A borrowed slice &[SafeInteger<_>] cannot be passed out to JS, since the elements have to be converted; pass a Vec or Box<[_]> instead.
